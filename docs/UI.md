# Stocker — локальный веб-интерфейс v1

Рутина без Claude Code: положил фото → видишь счётчики → разбираешь «Требует внимания» →
собираешь файлы к загрузке в плоские папки. Паспорт §35ZZZN.

## Запуск и остановка

| Действие | Как |
|---|---|
| Запустить без окна терминала | двойной щелчок `scripts\start_ui_hidden.vbs` |
| Запустить в окне (видно вывод) | `scripts\start_ui.cmd`; остановить — `Ctrl+C` (закрытие окна тоже останавливает) |
| Остановить | двойной щелчок `scripts\stop_ui.cmd` |
| Включить автозапуск при входе в Windows | двойной щелчок `scripts\install_ui_autostart.cmd` — задача планировщика «Stocker UI»: скрыто, перезапуск при сбое (3 раза через минуту); при «Access is denied» — запустить от имени администратора |
| Отключить автозапуск | двойной щелчок `scripts\uninstall_ui_autostart.cmd` (работающий интерфейс продолжит работать — остановить `stop_ui.cmd`) |

Открыть в браузере: **http://127.0.0.1:8780/**.

- **Лог:** `data\prod\logs\ui.log` — дописывается; при размере больше 5 МБ переименовывается
  в `ui.log.1` (хранятся `.1`–`.3`). Там же — строки запуска, повторного запуска и остановки.
- **Повторный запуск** при уже работающем интерфейсе ничего не делает (в логе «already
  running»). Если порт 8780 занят другой программой, интерфейс не запускается — причина в логе.
- `stop_ui.cmd` останавливает только процесс интерфейса на порту 8780 (MCP на 8765 и n8n не
  трогает); после такой остановки автозапуск интерфейс не перезапускает.

- Работает только на production-каталоге (`STOCKER_DATA_DIR=data/prod` задаёт скрипт);
  с тестовым каталогом не запускается.
- Слушает только `127.0.0.1` — с других компьютеров недоступен.
- Интерфейс сам файлы не регистрирует: новые фото обрабатывает живой контур (n8n + MCP),
  интерфейс показывает результат и принимает решения человека.

## Куда класть новые фото и что дальше

1. Положить готовый JPEG в **`data\prod\incoming\`** (с 02.10.2026, паспорт §35ZZZP).
2. В течение ~5 минут n8n (`stocker-ingest`) регистрирует файл и прогоняет pipeline:
   QC → Vision → metadata → gate → Readiness → Publication Gate. Дубликат (тот же SHA256
   под другим именем) не обрабатывается.
3. Результат — в интерфейсе (обновить страницу):
   - **Одобрено** — `publication_approved`: прошёл автоматически; дальше «Собрать к загрузке»;
   - **Требует внимания** — `human_review`: решение за человеком (причина на карточке);
   - **Заблокировано** — нужна аттестация людей или исправление файла.
   Итог ingest также приходит уведомлением n8n.

- Файл в `incoming` не удаляется и не перемещается — он остаётся исходником объекта.
- Черновики и промежуточные версии держать в **`data\prod\incoming_drafts\`** —
  туда n8n не смотрит.
- `data\incoming\` (тестовый каталог) больше автоматически не обрабатывается.

## Экраны

| Экран | Что делает |
|---|---|
| Панель | счётчики: одобрено и ещё не собрано, требует внимания, заблокировано, отклонено, проблемы с источником; недавние события; кнопка «Собрать к загрузке» (активна только когда «требует внимания» = 0) |
| Требует внимания | по одному объекту: превью до 2000 px, «Открыть 100%», причины человеческим языком (gate, QC, чёрные полосы с рекомендуемой обрезкой), title и ключевые слова — только чтение; «Одобрить», «Отклонить» (причина обязательна), «Пропустить»; при людях в кадре — «Люди в кадре не узнаваемы» (аттестация) |
| Одобрено | сетка превью, статус по площадкам (готов / в партии NNN), «Открыть 100%», «Вернуть на проверку» |
| Заблокировано | причина и что делать; для «Узнаваемые люди без релиза» — подтверждение «люди не узнаваемы» |
| Отклонено | объект, исходный файл, причина, дата |

**Формулировки без опоры на Vision** (`UNCONFIRMED_CLAIM`: имя собственное, число — например
«Flying» в заголовке, который не распознан как Title Case). Над кнопкой появляется переключатель
«Подтверждаю формулировки: <слова>». Без него одобрение не выполняется — интерфейс подскажет:
подтвердить или отклонить. С отметкой — `metadata.approve` с `confirm_claims=true` (как
`approve --confirm-claims` в CLI); подтверждаются ровно показанные слова — если список успел
измениться, интерфейс попросит обновить страницу.

Одобрение и «Люди в кадре не узнаваемы» — один шаг: сначала одобрение, аттестация
записывается только после успешного одобрения. Если одобрение не прошло, не записывается
ничего. Если объект одобрен, но следующий шаг (аттестация, Readiness, Publication) вернул
ошибку, она показывается на панели.

После «Одобрить» интерфейс, как и ручной поток, запускает Readiness и Publication — объект
становится одобренным для площадок. Одобрение человеком нельзя «вернуть на проверку»
(эскалация допускается только для автоодобренных) — интерфейс покажет сообщение.

## Собрать к загрузке

1. Для Adobe и Shutterstock: файлы площадки готовятся одобренным объектам без актуального
   экспорта; отказы показываются в отчёте.
2. `export.collect` копирует актуальные, ещё не собранные файлы в
   `data/prod/publish/<platform>/<NNN>_<YYYY-MM-DD>/` + `manifest.csv`
   (asset_id, filename, title / description, words, sha256). Повторный сбор — следующая
   партия только из новых файлов.

Загрузку на площадки интерфейс не выполняет.

## Безопасность

- Все действия — операции сервисного слоя от имени `human` (те же, что CLI / MCP).
- Каждый POST проверяет токен сессии сервера (новый при каждом запуске).
- Фото отдаются только по номеру объекта; путь из адреса не принимается.
